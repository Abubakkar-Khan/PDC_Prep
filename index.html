Theory.

1 · Parallel and distributed computing

Definitions

  • Serial computing: instructions run one after another on one processor.
  • Parallel computing: two or more processors, usually in one system, work at the same time on one problem.
  • Distributed computing: multiple computers, remote from each other, each have a role in one computation.
  • Parallel programming: writing programs that say which computations run in parallel.

Difference

ParallelDistributed
Multiple processors run tasks at the same timeNetworked computers coordinate by message passing
Usually one systemMultiple systems
Shared or distributed memoryEach computer has its own memory
Goal: performance, scientific computingGoal: resource sharing, scalability
Single master clockNo global clock; synchronization algorithms

Why parallel computing?

  • Save time: many processors work together.
  • Solve larger problems than one CPU and memory can handle.
  • Provide concurrency (databases, search engines).
  • CPU speed grew about 1000× in 20 years; DRAM speed grew less than 4×. CPU 1–2 ns, cache about 10 ns, DRAM 50–60 ns.
Example from classY = (4×5) + (1×6) + (5×3). One processor: 4 steps. Three processors compute 20, 6, 15 at once, then add: 2 steps.

Shared vs distributed memory

Von Neumann architecture

Input, output, control unit, ALU, memory and external storage. The CPU uses instructions and data to perform operations.

Concurrency vs parallelism

  • Concurrency: tasks start, run and finish in overlapping time periods. They need not run at the same instant (multitasking on a single core).
  • Parallelism: tasks literally run at the same time (multicore).

Why distribute? Distributed data

  • Data is collected and stored at different locations; moving it to one place is expensive.
  • Many tasks are inherently parallel.
  • Privacy issues in data mining and large commercial databases.
  • Example: Google used about 4,000 PC servers, one of the largest clusters.

Challenges in parallelism

ChallengeDetail
ComplexityMultiple instruction streams plus data flowing between them. Costs programmer time in design, coding, debugging, tuning and maintenance.
PortabilityStandards (MPI, OpenMP, POSIX threads) help, but implementations, operating systems and hardware differ. Vendor extensions hurt portability.
Resource requirementsWall-clock time falls but CPU time rises: 1 hour on 8 processors = 8 CPU-hours. Memory use can be higher (replicated data, library overhead).
OverheadFor short programs, setup, task creation, communication and termination can make parallel code slower than serial.

Performance: FLOPS and Amdahl

FLOPS (floating-point operations per second) measures computing power (theoretical peak). Example from class: IBM Summit, USA, 4,611,236 cores (9,216 POWER9 CPUs + 27,648 NVIDIA V100 GPUs), 122.3 PFLOPS. Amdahl's law: Speedup = 1/((1−P)+P/N) (see Numericals). FLOPS = sockets × cores/socket × cycles/s × FLOPs/cycle.

Parallel terminology (Lecture 4)

  • Supercomputing / HPC: using the world's fastest and largest computers to solve large problems.
  • Node: a standalone "computer in a box": multiple CPUs/cores, memory, network interfaces. Nodes are networked to form a supercomputer.
  • CPU / socket / processor / core: a CPU was once one execution unit. Then several CPUs went into a node. Then each CPU was split into cores (unique execution units). A multi-core CPU is a "socket". Result: a node with multiple CPUs, each with multiple cores. Servers can have more than one socket; home computers have 1. Cores per socket: 2 (dual), 4 (quad), 6 (hexa), 8, prototypes up to 80.
  • Clock rate: 2 GHz = 2,000,000,000 cycles per second.
Von Neumann and the speed gapVon Neumann machine: input devices, output devices, CPU (control unit + ALU), memory, external storage. Over time CPU speed outpaced RAM speed, and disk is slowest. This is why caches are needed (CPU 1–2 ns, cache 10 ns, DRAM 50–60 ns).

Serial vs parallel execution

Serial: the problem becomes a stream of instructions executed one at a time on one processor (example: do_payroll() handles emp1, emp2, emp3 in order). Parallel: the problem is divided into parts; each part is a stream of instructions on its own processor (do_payroll(emp1) … do_payroll(empN) at the same time). Parallel computing needs an overall control/coordination mechanism.

Definitions from the slides

  • Tanenbaum: a collection of independent computers that appear to the users as a single computer.

GPU programming: CUDA (NVIDIA) and OpenCL (portable). Uses: image processing, machine learning, video.

Process, thread, hybrid

  • Process: a running program with its own resources. Thread: an execution path inside a process; threads share memory.
  • Hybrid: MPI between computers + OpenMP threads inside each computer.

Parallel computer memory architectures

TypeKey points
UMA (Uniform Memory Access)Usually SMP (symmetric multiprocessor). Identical processors, equal access and equal access time to memory. CC-UMA = cache coherent: if one processor updates a location, all others know (done in hardware).
NUMA (Non-Uniform)Made by linking two or more SMPs. One SMP can access another's memory, but access across the link is slower. CC-NUMA if cache coherent.
Distributed memoryEach processor has local memory; needs a network. No global address space, so no cache coherency concept. Programmer defines how and when data is communicated and synchronized.
Hybrid distributed-sharedLargest computers use both: shared-memory nodes (or GPUs) networked together. Network communication moves data between machines.

Parallel programming models

  • Shared memory: Pthreads, C++ threads, OpenMP (comparatively better).
  • Distributed memory: MPI (MPI_Init, MPI_Send, MPI_Recv, MPI_Finalize), PGAS (Partitioned Global Address Space).
  • Accelerator / hybrid: part of the program on CPU, the rest on GPU (CUDA, OpenCL).

GPU details

  • A GPU has thousands of special-purpose processors, processes pixels of a 2D image in parallel, and follows the SIMD model.
  • NVIDIA GPUs have several streaming multiprocessors (SMs). Each SM has its own control units and memory (registers, L1 cache, shared memory) and several scalar processor (SP) cores.
  • CUDA = Compute Unified Device Architecture (NVIDIA).
  • GPU-accelerated computing = GPU + CPU for deep learning, analytics, engineering, video editing, medical imaging, AI, drones, robots, autonomous cars, IoT.

Threads, hyper-threading, multithreading

  • Process vs thread: both are independent sequences of execution. Threads of one process share memory; processes use separate memory.
  • Intel Hyper-Threading (HT): one physical core appears as two logical cores. A dual-core with HT shows 4 logical cores. It adds no physical cores; it overlaps threads to raise throughput.
  • Multithreading: software technique that runs multiple threads in a program; works with or without HT, on one or many cores. Improves responsiveness and performance.

GPU structure (Lecture 4 diagram)

A GPU has global memory, an L2 cache, an interface to the host, and a grid of SMs (streaming multiprocessors). Each SM contains many SP cores plus a warp scheduler and execution control, a register file, an L1 cache and shared memory.

4 · Data hazards extra

A hazard stops the next instruction from running in its planned clock cycle in a pipeline. A data hazard happens when instructions depend on each other's data.

TypeMeaningExample
RAW (true dependency)Read After Write: I2 reads a value before I1 writes itI1: ADD R1,R2,R3
I2: SUB R4,R1,R5
WAR (anti-dependency)Write After Read: I2 writes before I1 reads the old valueI1: ADD R4,R1,R2
I2: SUB R1,R5,R6
WAW (output dependency)Write After Write: writes finish in wrong orderI1: ADD R1,R2,R3
I2: SUB R1,R5,R6

In a simple in-order 5-stage pipeline, RAW is the common hazard. WAR and WAW appear with out-of-order execution.

Solutions

  • Stall (bubble): insert wait cycles. Simple but slow.
  • Forwarding (bypassing): send the ALU result directly to the next instruction. Removes most RAW stalls. A load followed by a use still needs 1 stall.
  • Instruction reordering: compiler moves independent instructions between the dependent pair.
  • Register renaming: removes WAR and WAW (false dependencies).
RememberOther hazard types: structural (two instructions need the same hardware) and control (branches).

5 · Memory hierarchy and cache coherence

Cache terms

  • Hit: data is in cache. Miss: data is not in cache.
  • Hit ratio = hits / total accesses. Miss ratio = 1 − hit ratio.
  • AMAT = hit time + miss ratio × miss penalty.
  • Temporal locality: recently used data is used again (a loop variable). Spatial locality: nearby data is used next (array in order).

Cache coherence

Keeps copies of the same memory location equal across caches. Without it a core can use an old value. Approaches: snooping (caches watch a shared bus) and directory-based (a directory records which caches hold a block).

Coherence vs consistency

Cache coherenceMemory consistency
Copies of one memory locationOrder and visibility of operations on different locations
Hardware protocols such as MESIDepends on architecture and programming model

Sequential consistency: all memory operations appear in one global order that keeps each thread's program order.

Class exampleInitially x=0, y=0. T0: x=1; print(y). T1: y=1; print(x). Can both print 0? Under sequential consistency, no: that needs x=1 before print(y), print(y) before y=1, y=1 before print(x), print(x) before x=1. This is a cycle, so it is impossible. Weaker hardware can allow it.

Synchronization and false sharing

  • Race condition: result depends on thread timing (a shared counter: read, add, write).
  • Tools: mutex/lock, atomic, semaphore, barrier, memory fence.
  • False sharing: different threads update different variables in the same cache line, so the line keeps bouncing. Fix: padding, per-thread data.

Why a hierarchy, and the shared counter race

One memory technology cannot be fast, large and cheap at once. In a multicore chip, cores have private L1/L2 caches, a shared L3 and shared RAM.

TimeThread AThread BCounter
t1read → 00
t2read → 00
t3add → 10
t4add → 10
t5write 11
t6write 11

counter = counter + 1 is three steps (read, add, write). Final value 1, expected 2. Coherence does not make this atomic.

#pragma omp parallel for
for (int i = 0; i < 10000; i++) {
    #pragma omp atomic update
    counter++;
}   // Final counter = 10000

Memory reordering

  • Compilers and processors may reorder memory operations to go faster, as far as the memory model allows.
  • Store buffers let a core continue before its write is visible. Out-of-order execution runs independent instructions early.
  • With a store buffer, both threads in the x/y example can print 0 on real hardware such as x86.
  • Coherence is not synchronization. A sleep or an ordinary print is not reliable synchronization. Use locks, atomics, barriers, fences.

Improving memory performance

  1. Access arrays sequentially.
  2. Reuse data while it is in cache.
  3. Organize data for spatial locality.
  4. Reduce unnecessary transfers.
  5. Avoid false sharing.
  6. Synchronize only where required.
  7. Measure before and after.
Class questionHit time 2 ns, miss ratio 5%, miss penalty 60 ns. AMAT = 2 + 0.05 × 60 = 5 ns.

6 · Interconnection networks

An interconnection network carries data between processors and memory. It is made of links (wires, fibre), switches and network interfaces.

Static (direct)Dynamic (indirect)
Point-to-point links between nodesSwitches and links connect inputs to outputs
Examples: completely connected, starExamples: bus, crossbar, Omega
  • Degree of a switch = total number of ports. Switch cost grows as the square of the degree.

Omega network

A multistage network with log₂p stages of 2×2 switches and a perfect shuffle between stages. It has (p/2)·log₂p switches, cost O(p log p). It is a compromise between bus (cheap, slow) and crossbar (fast, costly). It can block.

RoutingLet s and d be the binary source and destination. At each stage compare one bit (most significant first). Same bit: pass-through. Different bit: crossover. Example 010 → 111: cross, pass, cross. Blocking: 010→111 and 110→100 want the same link.

Why a network, and network sizes

  • Software wants dedicated channels between every processor and memory; hardware cannot afford the chip area and power. A network shares wires smartly.
  • Direct wires between all pairs: 8 cores need 28 wires, 100 cores need 4,950.
  • Design goal: move more data, in less time, within cost, power and area limits. A slow network becomes the bottleneck.

Switches and network interface

  • A switch maps a fixed number of inputs to outputs. Degree = total ports. Cost grows as the square of the degree (4-port ≈ 16 units, 8-port ≈ 64). Peripheral hardware grows linearly with degree; packaging cost grows with pins.
  • The network interface connects a processor to the network, on the I/O bus or the memory bus. Memory bus = faster, tightly coupled multicomputer. I/O bus = slower, cluster.
  • Commercial machines often mix topologies for packaging, cost and available parts.

Bus with caches, and examples

  • A bus with local memory/cache needs fewer bus trips and performs much better than one with no caches.
  • Real machines: bus (Sun Enterprise, Pentium shared-bus servers); crossbar (Sun Ultra HPC 10000, Fujitsu VPP500).
  • Bus has excellent cost scaling but poor performance scaling. Crossbar is the opposite. Multistage (Omega) is the compromise.

Perfect shuffle

Rule: output j = 2i if i < p/2, otherwise j = 2i + 1 − p.

7 · OpenMP (shared memory)

OpenMP is an API for shared-memory parallel programming in C, C++ and Fortran. It uses compiler directives and threads.

SyntaxPurpose
#pragma omp parallelCreate a parallel region (team of threads)
#pragma omp parallel forSplit loop iterations among threads
omp_get_thread_num()ID of the calling thread
omp_get_num_threads()Number of threads in the team
reduction(+:sum)Each thread keeps a private sum; OpenMP adds them
#pragma omp critical / atomicOne thread at a time updates shared data
#include <stdio.h>
#include <omp.h>
int main() {
    int sum = 0;
    #pragma omp parallel for reduction(+:sum)
    for (int i = 1; i <= 100; i++) sum += i;
    printf("%d\n", sum);   // 5050
}
// compile: gcc -fopenmp sum.c -o sum   run: ./sum
Race conditionTwo threads read the same old value of a shared counter and both write back. One update is lost. Fix: reduction, atomic, critical or lock.

The class lab uses Google Colab: first parallel program, thread IDs, parallel sum.

OpenMP in more detail

  • Three API components: compiler directives, runtime library routines, environment variables (e.g. OMP_NUM_THREADS).
  • History: ANSI X3H5 draft 1994; OpenMP specification started 1997; C and Fortran specs released together since 2005.
  • Designed for multi-processor/core shared-memory machines (UMA or NUMA).
  • Thread-based: parallelism only through threads. A thread is the smallest unit the OS can schedule and exists only inside a process. Usually threads = cores.
  • Explicit (not automatic) parallelism: the programmer has full control.
  • SPMD: all threads can run the same code but access different data and take different paths.
  • Nested parallelism and dynamic threads exist but implementations may not support them.
  • OpenMP says nothing about parallel I/O. The programmer must handle it.
What a thread-based model needsStart threads, discover how many are running, identify each thread, join threads, synchronize, keep a consistent view of data, and check for dependencies, data conflicts, race conditions and deadlocks.

8 · MPI (message passing)

MPI (Message Passing Interface) is a standard for communication between parallel processes. Each process has private memory and exchanges data by messages. It runs on one computer or many.

  • Rank: process ID inside a communicator (starts at 0, not an IP address). Size: number of processes. Communicator: group of processes; MPI_COMM_WORLD holds all.
FunctionPurpose
MPI_Init()Start MPI
MPI_Comm_rank()Get my rank
MPI_Comm_size()Get number of processes
MPI_Send()Send a message
MPI_Recv()Receive a message
MPI_Finalize()End MPI

MPI_Send(&value, count, datatype, destination, tag, comm)
MPI_Recv(&value, count, datatype, source, tag, comm, status). Tag, type and ranks must match.

MPI_Init(&argc, &argv);
MPI_Comm_rank(MPI_COMM_WORLD, &rank);
if (rank == 0) { value = 100;
    MPI_Send(&value, 1, MPI_INT, 1, 0, MPI_COMM_WORLD); }
else if (rank == 1) {
    MPI_Recv(&value, 1, MPI_INT, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
    printf("Process 1: Received %d\n", value); }
MPI_Finalize();
// mpicc mpi_demo.c -o mpi_demo     mpirun -np 2 ./mpi_demo

Collective operations

CallMeaning
MPI_BcastSame data from one process to all
MPI_ScatterSplit data, different part to each process
MPI_GatherCollect data from all at one process
MPI_ReduceCombine values (e.g. MPI_SUM) at one process

Blocking, non-blocking, deadlock

  • Blocking (MPI_Send/Recv): the call returns when it is safe to continue. Non-blocking (MPI_Isend/Irecv + MPI_Wait): starts communication and returns; do not reuse the buffer before completion.
  • Synchronous / asynchronous describe sender-receiver coordination; blocking / non-blocking describe when the call returns.
  • Deadlock: processes wait forever. Example: both processes call MPI_Recv first. Fix: reorder send and receive.

More MPI from the slides

  • Message passing idea: a process cannot read another's memory (Ali's notebook, Sara's notebook). Communication is explicit, unlike OpenMP where it is implicit.
  • MPI is an interface/standard, not a language (C, C++, Fortran). Implementations: MPICH, Open MPI (used in course), Intel MPI. A correct program runs on any.
  • Program structure: MPI_Init, get size, get rank, compute, communicate, MPI_Finalize. Ranks run 0 to size−1.
  • Compile mpicc hello.c -o hello; run mpirun -np 4 ./hello (or mpiexec). Same executable, four processes, four ranks. This SPMD style is a form of MIMD.
  • Typical use: weather forecasting. Each process computes a region, neighbours exchange boundary data each time step.
  • Reduce operations: MPI_SUM, MPI_MAX, MPI_MIN, MPI_PROD. The root (usually rank 0) receives the result. MPI_Ssend is synchronous: it finishes only when the receiver has started receiving.
  • MPI_Bcast(&value, 1, MPI_INT, 0, MPI_COMM_WORLD): root 0 sends to all.
int A[8] = {10,20,30,40,50,60,70,80};
int part[2], local, total;
MPI_Scatter(A, 2, MPI_INT, part, 2, MPI_INT, 0, MPI_COMM_WORLD);
local = part[0] + part[1];
MPI_Reduce(&local, &total, 1, MPI_INT, MPI_SUM, 0, MPI_COMM_WORLD);
if (rank == 0) printf("Total = %d\n", total);   // 360

Deadlock fix: swap the order on one side: P0 sends then receives; P1 receives then sends.

Solved examples

1. Parallel steps (Lecture 1)

Y = (4×5)+(1×6)+(5×3). Serial: 4 steps. 3 processors: multiply together (1 step), add (1 step) = 2 steps.

2. Speedup and efficiency

T₁ = 100 s, Tₚ = 30 s, p = 4. S = 100/30 = 3.33. E = 3.33/4 = 83%.

3. Amdahl (slide example)

P = 0.80 parallel, 1−P = 0.20 serial, N = 4. Speedup = 1/(0.20 + 0.80/4) = 1/(0.20 + 0.20) = 1/0.40 = 2.5. With infinite processors the limit is 1/0.20 = 5.

3b. FLOPS (slide test)
